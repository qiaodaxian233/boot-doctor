# 开机体检大师 (boot_doctor)

> Windows 开机体检 + 流氓软件清理 + 浏览器劫持检测 + 弹窗 / 通知拦截。
> 一键扫描开机全链路并给出处理建议；**所有修改先备份、随时可还原**；**开源，不上传任何体检数据**。

版本：v2.2.0 ｜ 环境：Windows 10 / 11 + Python 3.10 + PyQt5（`pip install -r requirements.txt`）｜ 需要管理员权限（程序会自动请求）

## 能做什么

| 模块 | 内容 |
|---|---|
| **开机体检** | 开机耗时与拖慢的程序、快速启动、自启项（Run / 启动文件夹 / 第三方计划任务）、服务残留、开机报错、隐蔽启动点（IFEO / Winlogon / AppInit 等 17 类）。每项给出「延迟 / 禁止 / 删除」，多选一次改 |
| **流氓软件** | 特征库三路匹配（1100+ 目录、400 签名主体、10 个全家桶家族），启动项 / 服务 / 已安装程序 / **正在运行的进程**都扫；**用数字签名核实「自称微软」**，公司名不当凭据；「疑似冒充微软」单独成项；运行中的可直接结束 |
| **浏览器劫持** | 系统代理（含「代理软件退出后没清掉导致上不了网」）、浏览器策略、IE 主页、hosts、被追加导航站网址的浏览器快捷方式 |
| **安全防护** | 检查有没有杀软在实时保护、Defender 病毒库新不新，并一键开启 Defender 的「潜在有害应用拦截」（PUA，专门拦下载器 / 捆绑推广软件，特征库由微软维护） |
| **实时防护** | 后台守护：弹窗拦截（事件钩子，窗口出现 0.2 秒内关掉）+ 开机自启监控（新增 / 被重新启用 / 命令被改，托盘立即提醒）+ **新进程提醒**（新启动的程序命中特征库 / 冒充微软时提醒，可选自动结束） |
| **通知管理** | 按应用关闭 Windows 右下角系统通知；命中特征库的标出来，可一键全关 |
| **备份还原** | 每次修改前自动快照，列表里选一个就能回到当时的状态 |

## 快速开始

| 步骤 | 操作 |
|---|---|
| 1 | `pip install -r requirements.txt`，然后双击 **启动体检.bat**（自动请求管理员权限） |
| 2 | 打开即显示**上次的体检结果**（标注「上次体检 X 分钟前 · 刷新中」），后台同时重新体检；也可按 **F5** 手动体检 |
| 3 | 看清单：「应用」列是这项属于**哪个软件**，「发布者」「签名」列告诉你是谁做的、有没有被改过 |
| 4 | 多选：**Ctrl** 点选 / **Shift** 连选，在底部「处理方式」点一次，这 N 项全部改掉 |
| 5 | 点 **智能优化（N）** 批量执行，或 **立即执行选中的 N 项**；出问题随时在左侧「备份还原」页还原 |
| 6 | 左侧导航切换页面：**Ctrl+1~4**（开机体检 / 实时防护 / 通知管理 / 备份还原） |

> 出厂策略：只勾选「安全级」项目；「需确认」的项目（含全部浏览器劫持类处理）默认不勾，自己判断后再勾。
> 排障时请用**重启**（快速启动只加速「关机→开机」）。

## 数据与隐私

- **体检数据不出本机。** 联网只有两处，都可以关：① 特征库更新（只拉 3 个公开文本，不下载程序）；
  ② AI 辅助判断（默认只连本机网关；改成非本机地址时设置里会二次确认，且只发「末两级路径」）
- 运行数据（备份 / 日志 / 设置 / 规则）默认放在程序目录；设环境变量 **`BOOTDOC_DATA_DIR`** 可改放别处
  （装在 Program Files 之类不可写位置时需要）。特征库和守护脚本属于程序本身，不跟着挪
- **VirusTotal 查询只发哈希**：右键「在 VirusTotal 查询这个文件」只把文件的 SHA-256 拼进网址、在你的浏览器里打开，
  **不上传文件，也不需要 API 密钥**；点了才会发生，体检本身从不联网查
- 「上次体检结果」缓存在 `_logs\last_scan.json`（超过 14 天自动忽略；设置里可关）

## 它能查什么

- **启动速度**：读系统启动性能日志（近 10 次开机耗时、登录阶段分段、反复拖慢的程序）
- **快速启动**：休眠开关 / hiberfil.sys 状态，未开启可一键开启（预计省 20~60 秒）
- **开机自启**：注册表 Run 系列 + 启动文件夹 + 任务管理器禁用状态，全量盘点；自动识别"更新器 / 预加载"类可关项
- **延迟 / 立即 / 禁止 / 删除（逐条四选一）**：每条可管理的服务、自启项、已建延迟任务，右下角都能选处理方式——**延迟启动**（错峰，仍启动）、**改回立即启动**（仅已延迟的项：删任务+恢复自启）、**禁止启动**（保留条目只禁用，随时恢复）、**彻底删除**（移除条目 / 注销任务，原值已备份）。删服务键风险太高，服务只提供前两种；失效残留走『服务与残留』。**多选时同一操作一次性应用到全部选中项**
- **延迟时长可选**：30 秒 / 1 / 2 / 3 / 5 分钟，改完即时刷新清单里的文案；已创建的延迟任务也列出来，可直接改时长或禁删
- **隐蔽启动点**：IFEO 映像劫持、Winlogon、AppInit DLL、BootExecute、Winsock LSP、LSA 安全包、打印机监视器等 17 类（普通启动项管理器看不见）
- **第三方开机 / 登录计划任务**：全家桶最爱用计划任务自启，任务管理器「启动应用」里看不到；逐条列出，带命令 / 发布者 / 签名，可禁止
- **流氓软件 / 全家桶**：特征库三路匹配 + 数字签名核实；已安装程序、启动项、服务都扫
- **浏览器劫持**：系统代理 / 浏览器策略 / IE 主页 / hosts / 浏览器快捷方式（详见更新说明）
- **服务与残留**：360 残留驱动、AlibabaProtect/AliPaladin、Intel 超时服务与遥测、luafv 噪音、失效服务键（指向已删除文件）
- **开机报错**：事件 7009/7000/7026/7031/7005/7023（含"配置注册表数据库损坏"诊断）
- **磁盘与其他**：C 盘空间、磁盘健康、计划任务数量、BIOS 层优化建议

## 智能修复（全部可还原）

| 修复类型 | 说明 |
|---|---|
| 开启快速启动 | `powercfg /h on` + 注册表开关（reduced 模式） |
| 调整服务启动类型 | 自动 → 手动 / 禁用（注册表 Start 值，带 ACL 兜底） |
| 关闭更新器类自启 | 任务管理器同款标记，随时能重新打开 |
| 禁止自启（单条） | 给指定自启项打「已禁用」标记：条目保留，任务管理器里可随时启用 |
| 彻底删除自启（单条） | 删除 Run 注册表值 / 启动文件夹快捷方式；原值或文件已备份，可还原 |
| 清理失效服务键 | 仅对"文件已不存在"的残留服务键，先存全量快照再删 |
| 禁用计划任务 | 如 Intel 遥测登录任务 |
| 延迟启动（服务） | 逐条改『自动（延迟启动）』：仍会启动，只错开开机高峰（Windows 原生机制） |
| 禁掉服务（单条） | 启动类型改为『禁用』，开机完全不加载；可随时还原 |
| 延迟启动（自启项） | 创建"登录后延迟 N"计划任务 + 关闭原自启标记；还原时自动清理任务 |
| 修改已有延迟任务 | 按顶部所选延迟时长重新登记（覆盖原任务），改完立刻生效 |
| 改回立即启动 | 删掉延迟任务 + 清掉原自启项的禁用标记；原条目已不存在则只删任务（避免幽灵自启项） |
| 禁止已有延迟任务 | `Disable-ScheduledTask`：任务定义保留、不再触发；还原按原状态启用 |
| 删除已有延迟任务 | `Unregister-ScheduledTask`：任务 XML 已复制进备份，还原时按 XML 重建 |
| 开启 Defender「潜在有害应用拦截」（`defender_pua`） | `Set-MpPreference -PUAProtection`，回读校验；被「篡改保护」/ 组策略锁住时如实失败，并告诉你到哪里手动开；原设置已备份 |
| 结束运行中的流氓软件进程（`proc_kill`） | 结束前核对「创建时间 + 程序路径」防 PID 复用误杀；系统目录 / 系统外壳进程 / 本程序自己一律不碰；**无法还原**，且不会清掉它的自启项 |
| 禁止第三方开机 / 登录任务 | `Disable-ScheduledTask`（带任务路径）：任务定义保留，可还原 |
| 修改浏览器 / 网络注册表设置（`reg_edit`） | 系统代理开关、浏览器策略、IE 主页、hosts 位置；原值含类型一并备份，原来没有的值还原时删掉 |
| 清理 hosts 被劫持的行（`hosts_clean`） | 整个文件已备份；保持原编码 / 换行 / 只读属性 |
| 清掉浏览器快捷方式里被追加的网址（`lnk_args`） | 只去掉多出来的网址，原快捷方式已备份 |

安全机制：
1. 每次修复前自动快照 → `_backups\<时间戳>\`（snapshot.json + restore-all.reg + 说明.txt）
2. 软件内 **还原…** 一键回滚（唯一完整方式）；`restore-all.reg` 只能覆盖注册表类改动
   （服务启动类型、自启项状态、Run 值）。**删除的服务键、禁用/删除的计划任务、
   启动文件夹里被移走的快捷方式都要走软件内还原**——`.reg` 表达不了这些，
   备份目录里的 `说明.txt` 会按本次实际改动逐条列出哪些必须用软件还原。
3. 不删除任何文件、不动软件数据；不碰杀软（火绒等）与用户自装工具
4. 自保护类软件（AlibabaProtect 等）运行时可能改不动 —— 重启后再执行一次即可

## 常见问题

- **这是杀毒软件吗？** 不是，别当杀软用。它做的是「清理 + 加固」：识别流氓软件 / 全家桶（靠**目录名、签名公司名、
  家族规则**的名单，不是字节特征码）、检查浏览器劫持和自启变化、关弹窗和通知。它**不读文件内容**，
  认不出改了名的陌生程序；也**不能在程序启动那一刻阻止它**（那需要内核驱动，火绒那种做法，风险和误报都大）。
  请和 Windows Defender 或火绒搭配使用——本工具的「安全防护」页会告诉你当前由谁在保护、PUA 开没开

- **修复需要管理员**：脚本会自动请求；若在软件里点修复，会提示"以管理员身份重启"。
- **某项修复失败**：多为软件自保护（如 AlibabaProtect），重启电脑后再点一次即可。
- **修复后没变化**：服务/驱动类修改在**下次开机**才完全生效；建议重启后重新体检对比。
- **想彻底卸载本工具的修改**：进 `_backups` 选对应备份点"还原"，再删掉 `boot_doctor` 文件夹即可。

# 更新说明

## v2.2.0 新增：浏览器扩展检查（浏览器劫持）

别的程序可以在注册表里「登记」Chrome / Edge 扩展（`HKLM\SOFTWARE\Google\Chrome\Extensions\<扩展 ID>` 等），
浏览器启动时照单安装 / 更新。Adobe、杀软等正规软件也这样做，但**捆绑推广软件最爱用它悄悄塞扩展**：改主页、注入广告、读浏览记录。

- 检查 Chrome / Edge 的 HKLM（含 Wow6432Node）和 HKCU 三处登记入口，只认 32 位 a-p 的扩展 ID
- 判定：更新地址是官方商店 → 提示（扩展来自商店，只是被登记）；更新地址不是官方商店 / 本地 `.crx` → 中危；
  **明文 http / IP 地址 / 导航站 / `.crx` 在 Temp、AppData 一类位置 → 高危**；登记的文件已不在 → 低
- 清除：删除整个登记键（含全部值和子键），**整键备份、可还原**（新修复类型 `reg_key_delete`）。
  **商店来源的只提示、不进清除清单**；公司 / 学校 / MDM 管理的电脑只提示。清除后浏览器通常会在下次启动时把对应扩展一并移除
- 强制安装（组策略 `ExtensionInstallForcelist`）的扩展由原有的「浏览器策略」检查负责

## v2.2.0 新增：新进程提醒（实时防护）

「正在运行的进程扫描」只在体检那一刻看一眼；推广程序往往是**安装后才冒出来**。现在守护进程顺带盯着：

- 每 1.5 秒对比一次进程列表（枚举约 10 ms，几乎不占 CPU）。**第一次只建基线**——守护启动前就在运行的不提醒，
  只对之后出现的新进程逐个判定
- 默认只报**高把握**的两类，避免天天弹提醒：命中流氓软件特征库（含签名核实）、公司名写 Microsoft 但签名不是微软。
  **严格模式**再加一类「没有数字签名、且从 Temp / AppData / ProgramData 启动」（很多安装程序会解压到 Temp 运行，所以默认关）
- 托盘提醒点一下打开到「实时防护 → 新进程」页签：提醒记录、查 VirusTotal；同一个程序 10 分钟内只弹一次，防刷屏
- **可选「命中特征库的新进程自动结束」**（默认关，开启时二次确认）：复用「结束进程」的身份核对（创建时间 + 路径），
  **只对开启之后出现的新进程动手**，之前就在跑的不追杀；系统进程和守护自己永远不碰。无法还原
- 开关改了**立即生效**（守护每轮重读规则文件）。测试里抓到过一个真问题：原来只在每 5 秒一次的全量扫描时才重读，实际会晚最多 5 秒
- 局限：1.5 秒内启动又退出的进程会漏掉（不是内核级监控）。要在启动那一刻拦截，需要内核驱动，本工具不做
- `BOOTDOC_ADWARE_DB` 环境变量可指定自定义特征库路径

端到端测试（真守护进程 + 真子进程 + 一份只含「python 所在目录」的自定义特征库）：基线进程不报、新进程被提醒、
自动结束只动新进程、总开关关了不再动。

## v2.1.0 新增：安全防护三件套（Windows 自带防护 / VirusTotal 哈希 / 运行中进程）

**设计思路**：下载器、捆绑推广软件的「特征码」（字节特征 / 哈希）是杀毒厂商靠样本和人工持续积累的情报，
一个开源小工具追不上。所以这一版不自己造特征码，而是：借用 Windows 自带的、持续更新的防护，
加上不依赖特征码的行为判断。

- **安全防护（新分类）**：在磁盘查询的同一个 PowerShell 进程里顺带查 Defender 状态 / PUA 设置 /
  SecurityCenter 的杀软列表，不多起进程。报：没有杀软在实时保护（服务器降为提示）、病毒库 7 天没更新、
  PUA 没开。装了第三方杀软（火绒等）时 Defender 会自动退居被动，只提示由谁负责，不劝开 PUA
- **一键开启 PUA**：Windows Defender 自带的「潜在有害应用拦截」，专门拦下载器 / 捆绑推广软件。

## v1.9.0 新增：弹窗拦截（定位 + 规则 + 后台守护）

入口：`操作 → 弹窗拦截…`（Ctrl+Shift+P）

### 为什么不用火绒那套

先查了现有的东西，结论写在这里免得以后重复研究：

| 项目 | 做法 | 能不能用 |
|---|---|---|
| 火绒「弹窗拦截」 | 驱动 + API Hook（CreateWindowExW），内置规则库 | **规则不公开**，藏在 `hrpui.dll` / `rulemgr.dll` / `popupfilter.sys` 里 |
| 网上流传的「火绒弹窗拦截独立版」 | 从安装包提取私有 DLL 重新拼装，或注入汇编钩子 | 二进制闭源、随火绒升级失效、杀软会报；**不碰** |
| PopupBlocker（GitHub） | 全局 `WH_CBT` 钩子，窗口创建前就拦掉 | 无许可证、需注入；**不碰** |
| PopKiller（MIT，5★） | 规则 + 启发式 + ONNX 双模型 | 只借了 4 个进程名，算法思路参考 |
| PopupGuard（C#，1★） | 轮询 + 截图选窗 + 窗口记录 + 托盘 | 交互设计参考（**截图选窗 / 窗口记录** 就来自这个思路） |
| ad-blocker-rules | 30 个软件 / 65 条 `conditions+action` 规则 | **无许可证**，只参考格式、不抄数据 |

所以最后走的是「不注入、不挂钩子、只发 WM_CLOSE」的路线：能做的事少一点，但不会把系统搞坏，
也不会被当成外挂。规则主要来自我们自己的流氓软件特征库（1138 目录 + 397 签名 + 10 家族），
再加一份小规模的「纯广告进程」名单（`flashcenter.exe` / `minipage.exe` 等 4 个来自 MIT 的 PopKiller）。

### 三个能力

1. **弹窗定位**：列出桌面所有窗口的「标题 / 进程 / 发布者 / 路径 / 判定」，命中特征库的排最前，
   直接回答「这广告到底是谁弹的」。
2. **截图选窗**（火绒同款）：点「选取窗口…」，3 秒内把鼠标移到弹窗上不用点，
   自动抓 `WindowFromPoint` 的顶层窗口，识别进程 / 类名 / 标题后一键加规则。
   不点鼠标是关键——很多弹窗的「关闭」是假按钮，点了就跳广告页。
3. **窗口记录**（火绒同款）：守护进程把见过的窗口记到 `_logs\popup_watch.log`，
   弹窗一闪而过也能事后回溯、直接加拦截。

### 规则与安全边界

- 规则文件 `_popup_rules.json`，支持 `proc / proc_contains / path / title / class / class_contains`
  六种条件，也支持 `all` 组合条件（必须同时满足）
- 可导入社区那种 `conditions + action` 格式（用户自己下载的规则文件），自动转换
- **只发 `WM_CLOSE`**：等于点右上角 ×，不杀进程、不注入、不改文件
- 系统窗口（任务栏 / 桌面 / UWP 外壳）和系统进程（explorer / dwm / winlogon…）**无条件放过**，
  用户写规则也压不住
- 同一窗口 30 秒内不重复发消息，避免和顽固程序死磕
- 默认关闭，必须自己点「开始后台拦截」；随时从托盘或界面停止

### 实测

造了一个标题为「测试弹窗广告」的窗口，守护启动后 **0.6 秒**被关掉（一个轮询周期），
日志同时写入拦截记录与窗口记录。

### 已知限制

- **系统通知类弹窗拦不了**：那类不是独立窗口，是 Windows 通知中心渲染的。
  v2.0.0 起可以在左侧「通知管理」页按应用关掉（和「设置 → 系统 → 通知」是同一个开关）。

  这部分用「流氓软件 / 全家桶扫描」里的右键卸载。

## v1.8.1 修复：拖动卡顿 + 窗口过大 + 光标变缩放箭头

三个症状，两个根因，都跟 4K 屏 + 150% 缩放有关。

### 症状 1：拖动 / 滚动特别卡

**不是亚克力的问题。** 实测拖动时帧间隔稳定 16.5ms（60fps），亚克力开关无差异。

真正的瓶颈是**表格图标**：

| 状态 | 28 行表格重绘 |
|---|---|
| 直接塞 `QFileIconProvider` 返回的原图 | **42ms/帧**（≈24fps） |
| 预缩放到 16×dpr 再缓存 | **13ms/帧** |

`QFileIconProvider.icon()` 给的是 32×32 甚至 48×48 的原图，表格只要 16×16，
于是每一行每一帧都要做一次高质量缩放，4K 屏还要再乘 dpr=2。28 行就是 28 次缩放。

改成在 `_app_icon()` 里按 `16 × dpr` 预先 `pixmap()` + `scaled()` 好再缓存，
绘制时直接 blit。顺带给 `_dot_icon()`（等级圆点）和 `win_brush()`（窗口渐变）也加了缓存。

### 症状 2：打开窗口特别大

`AA_EnableHighDpiScaling` 生效后，逻辑分辨率是物理的 1/dpr。这台机器是
3840×2160 + 150% 缩放 → 逻辑 1920×1080。

原来的尺寸算法写死了上限：

```python
w = max(1000, min(1400, int(avail.width() * 0.94)))   # 上限 1400
```

1920 宽下 1400 只占 73%，但系统再把它拉伸 1.5 倍显示，观感就是"占了大半个屏幕还很糊"。
改成按比例取（86% × 88%），且最小尺寸也跟随屏幕 —— 小屏笔记本（1366×768）
和虚拟桌面（800×600）都不会超出可用区。

### 症状 3：鼠标移到操作区就变成缩放箭头

这个是真正的 bug，也是 4K 缩放最容易踩的坑：**坐标系统不一致**。

```
WM_NCHITTEST 的 lParam  →  物理像素（3840 坐标系，不受 DPI 缩放影响）
frameGeometry()          →  逻辑像素（1920 坐标系）
```

原来直接拿两者比较，在 150% 缩放下差 1.5 倍、200% 下差 2 倍。表现为判定区域整体
偏移，鼠标在窗口中间就被判成"底边"，光标变成上下缩放箭头。

修复：把 `lParam` 除以 `devicePixelRatio` 换算到逻辑坐标再比；抓边宽度也按 dpr 缩放；
落在客户区时明确返回 `HTCLIENT(1)`，不让系统继承到缩放光标。

验证：9 个位置全部通过 —— 正中心 / 内容区四角 → `HTCLIENT`，四条边 → `HTLEFT/RIGHT/TOP/BOTTOM`。

  该禁止的自动改成「禁止启动」、该延迟的改成「延迟启动」，最后仍由你点『智能优化』执行。
  右键任意行还有 **问 AI：这程序能关吗？**，单项解读更详细。
  默认网关 `http://127.0.0.1:3425`、模型 `workbuddy-ai/hy4flash-free`；**右键 AI 按钮**可改，写进 `_settings.json`
- **看得懂是哪个软件**：每行显示程序图标 + 文件说明 + 文件名（如 `AdGuard for Windows · Adguard.exe`），
  第三列双击 / 右键「查看这是哪个应用」可看完整路径、公司、版本、启动参数
- **右键直接改状态**：`立即切换为 → 延迟启动 / 改回立即启动 / 禁止启动 / 彻底删除`，
  不必勾选再等批量；执行前照样自动备份
- **改回立即启动**（新增第四种处理方式）：删掉延迟任务 + 清掉原自启项的「已禁用」标记，
  登录后立刻启动，和改延时之前一样；原自启项已被删掉的只删任务，不会造幽灵条目
- **文件失效提示**：自启项指向的 exe 不存在时标红 `⚠ 找不到文件`，并列出同目录现存程序，
  方便判断是卸载残留还是软件改名（例：`WorkBuddyAI.exe` 已改名成 `WorkBuddy.exe`）
- **命令解析兜底**：裸文件名（`CTHELPER.EXE`）按 App Paths → System32 → PATH → 常见安装目录依次解析
